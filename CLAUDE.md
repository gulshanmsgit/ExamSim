## Question packs (the main ongoing work)
**Before creating or editing any questions, follow the standard below** (planner = subjects/topics, syllabus PDF = sub-topic sets,
split recorded in `tools/syllabus_map.json` first; `python tools/check_packs.py` must show 0 errors before committing):

@QUESTION_STANDARD.md

- A pack is JSON: `{examsimPack:1, name, description, subjects:[{name, icon, topics:[{name, plan?, sets:[{name, questions:[…]}]}]}], mocks?}`.
  Import merges by **name** (subject, topic, set) — re-import is safe (existing set names are skipped).
- `packs/index.json` lists packs for the Question bank (`group`, `file`, `name`, `description` by hand; `questions`, `topics`, `subjects`, `planIds` by `tools/make_index.py`). Add every new pack there, then run make_index.
- `packs/gpstr-cst-2026-00-structure.json` = all subjects/topics from the planner (17 subjects, 194 topics, plan dates, Paper 1 + Paper 2 mock presets), generated by `tools/make_structure.py`. Current affairs are not in the structure pack; they live in the separate monthly subject **P1 · Current Affairs** (see QUESTION_STANDARD.md §7).
- Subject names: `P1 · General Knowledge`, `P1 · General Kannada (ಸಾಮಾನ್ಯ ಕನ್ನಡ)`, `P1 · General English`, `P1 · Educational Psychology`, `P1 · Computer Literacy`, `P1 · Health Education`, `P1 · Value Education`, and `P2 · Unit N – <planner unit title>` (e.g. `P2 · Unit 3 – Computer System Architecture`). **Topic names must match the planner topics exactly** (en dash `–`); builders assert this against the structure pack (see `tools/pack_p2_u2.py`).
- Build tooling: `tools/packlib.py` → `build_pack(out, name, description, subjects)`. Questions are tuples `(question, [4 options], correct_index, explanation)`; helpers `AR` (assertion–reason options) and `I_II` (Only I / Only II / Both / Neither). It shuffles options deterministically and balances A–D per set (correct answer goes to the least-used letter; AR/I_II keep their order, so pick their answers deliberately), and fails on duplicates, bad options or bad answers, and prints the A–D spread.
  Content lives in modules (e.g. `tools/p2u2_a.py … p2u2_e.py`) exporting `TOPICS = {planner topic: [("1 · Sub-topic", QUESTIONS), …]}`; a `tools/pack_*.py` script assembles and writes `packs/*.json`.

### Content rules the owner asked for
- **Paper 2: English only; 30 questions per syllabus sub-topic**, one question set per sub-topic inside its planner topic
  (set names like `1 · Basics of Counting`, `tag` = sub-topic name so results break down by sub-topic).
- **Higher difficulty** (GPSTR/CST level, UGC-NET CS style for Paper 2): multi-statement, "which is INCORRECT", assertion–reason,
  match-the-following, scenario and numerical questions, each with a short explanation (worked numericals).
- **Vary the answers**: assertion–reason and I/II answers must not all be A / "Only I" (this was a real flaw that was fixed); aim for a roughly even A–D spread.
- Paper 1 General Kannada: questions in Kannada (KTBS textbook basis).
- Current affairs: monthly from January 2026, 75% Karnataka / 25% national, web-researched and source-cited (QUESTION_STANDARD.md §7).
- Accuracy first: if unsure of a fact, write a different question. Sources: syllabus reference books (Sinha, Rosen, Elmasri & Navathe, Silberschatz, Forouzan, Mano, Pressman, Russell & Norvig…).

### Notes, navigation and Home (built 26 Sep 2026)
- **Notes** (screen `notes`, `openNotes(topicId)`): Markdown notes per topic in `notes/{id} = {topicId, title, md, source, order, createdAt, updatedAt}`;
  `topics.notes` keeps the count. Made for pasting AI answers: Markdown is kept as typed; pasted HTML (text/html without Markdown markers) is converted
  with turndown + GFM (KaTeX spans → `$tex$`, buttons dropped). Rendering: marked (gfm, breaks) + DOMPurify; maths `$…$`, `$$…$$`, `\(…\)`, `\[…\]`
  via KaTeX (loaded only when needed). Libraries are lazy-loaded from cdn.jsdelivr.net (versions pinned in `LIBS`). Notes can be edited, reordered,
  appended to ("Save as: add to the end of …") and merged (select ≥ 2). Entry points: topic page card, 📝 buttons on Home and Study plan task rows,

  back gesture works via `popstate` → `openRoute()`. Non-rebuildable screens (exam, setup, add, revise, mock builder) are skipped; leaving a running exam asks first.
